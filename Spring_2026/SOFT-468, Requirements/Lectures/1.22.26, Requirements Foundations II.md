A <mark style="background: #ADCCFFA6;">goal</mark> is a statement formulated entirely in terms of World phenomena and is to be enforced by Machine in collaboration with other agents in the World
A <mark style="background: #ADCCFFA6;">software requirement</mark> is a statement formulated entirely in terms of shared phenomena to be enforced by the Machine alone
	Prescriptive statement about a system, same as goal
A <mark style="background: #ADCCFFA6;">domain assumption</mark> is a statement formulated entirely in terms of World phenomena and it is to be enforced by World components other than the Machine
	Descriptive statement about a system

Descriptive indicate facts or beliefs, prescriptive indicates wishes

A <mark style="background: #ADCCFFA6;">designation</mark> is an information description of what a term represents in the World
	Keyword: IS
A <mark style="background: #ADCCFFA6;">definition</mark> is a formal description that defines the meaning of a term in terms of other defined or designated terms
	Keywords: IS DEFINED AS

The <mark style="background: #ADCCFFA6;">Machine</mark> denotes the product to be developed. The software to be + the hardware on which it executes
The <mark style="background: #ADCCFFA6;">World</mark> denotes the part of the real world relevant to the development project
<mark style="background: #ADCCFFA6;">World Phenomenon</mark> is a phenomenon that can be observed in the World
<mark style="background: #ADCCFFA6;">Machine phenomenon</mark> is a phenomenon that can be observed in the Machine
A <mark style="background: #ADCCFFA6;">shared phenomenon</mark> is a phenomenon that can be observed at the interface between the World and the Machine

<mark style="background: #BBFABBA6;">Machine inputs are shared phenomena controlled by the World. Machine outputs are shared phenomena controlled by the Machine</mark>

<mark style="background: #BBFABBA6;">It can be easier to think of world phenomena as what happens to/around the machine.</mark> Like above, what happens to the machine is the plane flies or lands or gives reverse thrust or turns the wheels. Another example is for an online ordering system, the world phenomena would be the item delivered only if paid for, which is what happens around the machine without any technical details. Ask yourself, <mark style="background: #BBFABBA6;">what happens to or around this system?</mark> 

<mark style="background: #BBFABBA6;">Machine phenomena is REALLY specific to the software/hardware.</mark> Like it will specifically name the functions or variables involved. <mark style="background: #BBFABBA6;">Ask yourself, what does this system do and how does it do it?</mark> Usually phrased as information processing or control flows
