Goals of the parser, given an input program:
- Find all syntax errors; for each, produce an appropriate diagnostic message and recover quickly
- Produce the parse tree, or at least a trace of the parse tree, for the program

Two categories of parsers:
- Top down - produce the parse tree, beginning at the root
	- Key Problem: Identify which production of a non-terminal must be chosen such that the terminals in the production body match the terminals in the input string
	- Backtracking is computationally expensive
- Bottom up (or shift-reduce) - produce the parse tree, beginning at the leaves
	- Read input string from the left to the right
	- Build parse tree from the right to the left, ie we use the grammar in the opposite way (reverse parsing), from the right to the left
	- Two rules in bottom up parsing:
		- Reduction rule: if the first few symbols (tokens) (of the input string) at the top of the stack match the RHS of some rule, we pop out these symbols from the stack and push the LHS of the rule
		- Shift rule: shift the current input token in the stack and read the next token
	- Key problem: figuring out when to reduce in ambiguous languages. when to apply rules if youre going left to right?

Recursive descent parsing:
- Has a set of sub-procedures
- One sub-procedure is for one non-terminal in the grammar
- The parsing starts with the execution of the sub-procedure for the starting symbol
- EBNF () is ideally suited for being the basis for a recursive-descent parser because complexity is determined by non-terminals, so the more non-terminals the more complex, and EBNF will minimize the number of non-terminals

		else if (Xi = current input symbol a)

		else an error has occurred
	}
}

## BISON
Bison
- Parser generator which is a modern version of yacc (yet another compiler compiler), a UNIX tool
- Converts CFG to a C program to parse the grammar
- Bison parser implements bottom-up parsing
- Bison input file defining a CFG is in *.y

The parsing technique used by yacc is LALR(1) or Look Ahead Left Recursive; (1) indicates that the lookahead is limited to one token
lex and yacc communicate through a global variable named yylval

Conflicts
- Shift-reduce conflict: yacc will always shift
- reduce-reduce conflict: yacc will always use the first rule to reduce

yacc maintains two internal stacks
- Parse stack
	- Contains terminals and non-terminals
	- returned by int yylex()
- value stack
	- contains values of type YYSTYPE (int by default)
	- YYSTYPE is defined in filename.tab.h
	- pushed from variable yylval

How to use bison:
1. Write a lexical analyzer using flex to process input and parse tokens to the parser
2. Write the grammar specification for bison
3. Run bison on the grammar to produce the bison parser
4. Bison parser defines a function named yyparse() which implements the grammar
5. yyparse() does not make a complete C progra. You must supply additional functions, one is the lexical analyzer (yylex()) from flex and other is error-reporting function yyerror()
6. Compile parser file generated by Bison to generate executable code
7. Execute the executable parser to produce the result

To define a language for Bison, write a file expressing the grammar in Bison syntax (this is the bison grammar file)
- A nonterminal symbol in the formal grammar is represented in bison input as an identifier
- A terminal is called a token kind

A formal grammar selects tokens only by their classification. However, the precise value is very important for what the input means once it parsed. Therefore, each Bison grammar has both a token kind and a semantic value stored in a global variable yylval. The datatype for this is YYSTYPE
