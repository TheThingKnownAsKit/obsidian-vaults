# Sorting Objects
**Natural Order** is like the numerical or alphabetical or other ordering of some primitive value.
If an object does not have a natural order you can use to sort it it gets complicated. Do not implement comparable in the object class. There are so many different ways to decide to sort objects that it's basically useless.

## Comparator Interface
**Comparator** objects are external objects that specify a comparison function over some other type of objects.
* Allows you to define multiple orderings for the same type
* Allows you to define a specific ordering for a type even if there is no obvious "natural" ordering

```
public class RectangleAreaComparator implements Comparator<Rectangle> {
	// compare in ascending order by area (WxH)
	public int compare(Rectangle r1, Rectangle r2) {
		return r1.getArea() - r2.getArea();
	}
}
```
Notice it's its own class who's only purpose is to compare two objects based on a specified criteria.
```
public class RectangleXYComparator implemenets Comparator<Rectangle> {
	// compare by ascending x, break ties by y
	public int compare(Rectangle r1, Rectangle r2) {
		if (r1.getX() != r2.getX()) {
			return r1.getX() - r2.getX();
		} else {
			return r1.getY() - r2.getY();
		}
	}
}
```

Searching and sorting methods can accept Comparators.
`Arrays.binarySearch(array, value, new comparator);`
`Arrays.sort(array, new comparator);`
`Collections.binarySearch(list, new comparator);`
`Collections.max(list, new comparator);`
`Collections.min(list, new comparator);`
`Collections.sort(list, new comparator);`
`Collections.reverseOrder(new comparator);` <- returns a new comparator object with the opposite ordering
If the array implements comparator, you do not need to provide the comparator.
You make a new comparator object for each sort generally.

Note: Comparator and Comparable are not exclusive. The object can implement Comparable and have a defaultish compareTo.
