## CHAR DATA TYPE
- single character
- 16 bit
- Stored in memory as an unsigned integer
- NO TWO'S COMPLEMENT, 1 in the leftmost does not mean negative, you cannot have a negative character
- Because it's an integer type, you can use most basic math operations on char
- Single quotes like 'h'

When you do math operations on char's, it will turn it into an int, so you have to cast it back to (char) to return a character.
An int and doubles can equal a char. Like you can do int myInt = 'a' and it will equal 97.
Char can equal basically anything besides a boolean for some reason java is weird (works on int, double, short, byte(even though a byte is less than 16 bits???))

## STRINGS
A string is an object storing a sequence of text characters
Unlike most other objects, a String is not always created with new. Since it is used so often it can be used as any other primitive data type (when declaring/initializing at least)

In strings + signs are concatenation operator and not addition.
You can also do str1.concat(str2) returns a new string that appends str2 to str1. Same as +

Characters of a string are numbered with 0based indexes: It's the position number (starting from 0) and moving from left to right. INCLUDING WHITESPACE. The value at the index is stored as a char

## STRINGS & IMMUTABILITY & MEMORY ADDRESSES
Immutability means not changeable.
A string once created cannot be modified.

This does not mean that a string VARIABLE cannot be modified. The only way to change the value of a String is to create a new String and point to that instead
You can act like you can change it in code, but if you change it, it will actually just create a new value at a new address and assign it to the variable.

If you do this, Java is always checking to see how many pointers a reference variable has. If a value in an address has no pointers anymore because the String or whatever was assigned a new address, it will only exist for a second or fractions of a second before it is deleted from memory.

NOTE: Not every reference type is immutable. Sometimes you can change what is stored in the memory.
Specifically for strings, because they can be so large in size they are immutable because the OS wants to know how much memory it is going to take up.
The immutability of strings is really only important for comparison purposes. If you do something like stringOne == stringTwo, it's comparing memory addresses, not actual data value. Even if the addresses hold the same string, if they are not the same address it will return false.

Variable data always has an address in memory wherever there is room for data of its size in bits. Variable names just point to the address of the stored data.

The address is usually an 8 digit hex string. Each digit can hold 4 bits of info, 4 * 8 is 32. Hence 32-bit operation systems. It's the maximum value a memory storage addresses can hold. (Note: not the max amount of memory slots available, but the maximum number of digits an address can have)
Most computers use 64-bit OS systems, but Java is coded in 32 since it was made before 64.

You can think of memory as a grid and each space on the grid is one address.

NOTE: things like strings point to data addresses. Primitive data types like integers do not point to an address, it is just the integer.
Strings can point to the same address, but they can also technically hold the same value but have different addresses.
There is a table for every java program that keeps track of the variables. For example:
int b = 7
String demoString = "cat"

|   |   |
|---|---|
|b|7|
|demoString|AD74H23B (this is the address for the memory space where "cat" is stored)|

Hence why the two data types are primitive data types and reference types, because they just reference the address of the memory slot where the data is stored.

NOTE: the address of reference types is called the pointer.
