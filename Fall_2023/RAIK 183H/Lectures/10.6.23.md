**Value semantics**: Behavior where values are copied when 1.) assigned, 2.) passed as parameters, or 3.) returned.
* All primitive types in Java use value semantics
* When one variable is assigned to another, its **value is copied**
* Modifying the value of one variable does not affect others.
* Modifying the parameter in the function's scope will not affect the variable from the calling scope.

**Reference semantics (objects)**: Behavior where variables actually store the address of an object in memory. Often called a pointer
* When one variable is assigned to another, the object is **NOT COPIED; the reference to the object is copied**. It stores a pointer to the original object's memory address.
* If you edit the parameter variable of a mutable object, it will change the original variable as well. (arrays)
* If you edit the parameter variable of an IMMUTABLE object, it will not change the original object because it will create a new memory address to store the value. (strings)
* This is mostly for efficiency. Copying large objects slows down a program.
  It is also used for sharing. It's useful to share an object's data among methods.
  It is also safer data security wise.

public static void swap (int[] array, indexOne, indexTwo) {
	int temp = array[indexOne];
	array[indexOne] = array[indexTwo];
	array[indexTwo] = temp;
}
