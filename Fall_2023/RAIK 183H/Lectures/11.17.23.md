5. Avoid creating unnecessary objects
	1. Memory, slow processing
	2. Create static variables when possible, use **static blocks**
6. Eliminate obsolete references
	1. Null out values can SOMETIMES help
45. Minimize the scope of local variables
	1. Declare variables the first time they are used
	2. Except try/catch blocks. You usually want to use the variables outside their scope
51. Beware the performance of string concatenation
	1. Strings are immutable, it's making an entire new string every time
	2. Fix it with **StringBuilder.** This is to String as ArrayList is to an array. It is mutable. It can be initialized with a specific size to prevent it from needing to grow
		1. DIFFERENCES:
			1. StringBuilder needs to be initialized with the new keyword
			2. Concatenation happens with the append(String strToAppend) function
			3. To get your final String out of the StringBuilder, call toString()
			   `StringBuilder strBldr = new StringBuilder();` You could add an optional size into the `StringBuilder(size);`
			4. You don't return the StringBuilder itself, you return the string
55. Optimize Judiciously
	1. There are two rules of optimization.
	   1.Don't do it
	   2.(for experts only) don't do it yet - that is, not until you have a perfectly clear and unoptimized solution
   2. It's easy to do more harm than good. It makes it harder to test and read. It is better to write good programs than fast one. Balance it.
   3. This does not mean don't think about memory management. If it's easy and not costly, optimize
	   1. Don't intentionally make expensive decisions that will be difficult to change
	   2. You can make them but make it easy to change to a less expensive if need be (utilize abstraction)
	   3. It is a very bad idea to warp an API to achieve good performance.

More tips:
* When you have an even choice, prefer for loops to while loops
	* The counter exits the scope at the end of the loop, but if you needed one in a while loop it would not
* Keep your loop variables inside your loop
* Single responsibility principle - short focused methods inherently have smaller scopes
	* Each method should only do one thing
	* Industry standard is 40 lines per function. Do not go above 100 because that'll cause memory leaks

## Static Blocks
Java supports a special block, called a **static block** (also called static clause) which can be used for static initializations of a class
If you want to make a static field variable that calculates something, it needs to be in a static method that constructs the static data. Java only allows calculations within methods.
It is executed only one time. 
	The first time you make an object of that class (executed before the constructor)
	The first time you access a static member of the class (even if an object is never made)

Example
```
Class Test {
	static int 1;
	int j;
	
	// start of static block
	static {
		Random random = new Random();
		i = random.nextInt(10);
		System.out.println("static block called");
	}
	// end of static
}

Class Main {
	public static void main
}

```

```
public class Person {
	private final Data birthDate;
	private static final Date BOOM_START;
	private static final Date BOOM_END;
	
	static {
		Calendar gmtCal = Calendar.getInstance(TimeZone.getTimeZone("GMT"));
		gmtCal.set(1946, Calendar.JANUARY, 1, 0, 0, 0);
		BOOM_START = gmtCal.getTime();
		
		gmtCal.set(1965, Calendar.JANUARY, 1, 0, 0, 0);
		BOOM_END = gmtCal.getTime();
	}
	
	public boolean isBabyBoomer() {
		return birthDate.compareTo(BOOM_START) >= 0 && birthDate.compareTo(BOOM_END) < 0;
	}
}
```
