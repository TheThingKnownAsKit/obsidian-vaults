# Searches
## Linear Search
You just go down the list checking each item.
Very inefficient but easy to read/write.
Sorting can make it faster.

## Binary Search
* Starting in the middle
* Compare what's there with the thing you're looking for
	* Is the middle item less than or greater than what you're looking for?
* Decide which half of the remaining entries to look at
* Repeat until the middle item IS what you're looking for or it does not exist in the list
**Binary Search Algorithm**

Requires a sorted list

When it moves the lower bound or upper bound, it shifts it one to the right/left of the middle index since that index has already been checked.

If even, it'll go to the lower index because of integer division.

```
public static int binarySearch(int needle, int[] haystack) {
	int hi = haystack.length - 1;
	int lo = 0;
	
	while (hi >= lo) {
		// set mid
		int mid = (hi + lo) / 2;
		
		// if mid is our element, return mid
		if (haystack[mid] == needle) {
			return mid;
		}
		// look left
		else if (needle < haystack[mid]) {
			hi = mid - 1;
		}
		// look right
		else {
			lo = mid + 1;
		}
	}
	
	// item wasn't found, return the index where the element WOULD HAVE been
	return -hi -1;
}
```
the -1 is there incase it's 0.
Can also just do `Arrays.binarySearch`
Returns the index of the element if it exists, OR returns the index where the element should be inserted (minus one)

SIGNIFICANTLY FASTER.
Worse case scenario for a list with 1,000,000 elements is just 20 searches.

Equation to determine how many searches it will take to find an element in the worst case scenario for a list of N elements.
$[\log_2N]+1$
$[\log_2 32]+1=6$ so 6 searches for a list of 32 elements.
