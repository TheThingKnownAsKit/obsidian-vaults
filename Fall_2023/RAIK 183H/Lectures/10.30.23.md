## String processing & file I/O
### Manipulating/creating a file
Hard drive SIGNIFICANTLY slower than memory. Has a ton of boxes with addresses.

| Directory name | Size | Name            | is dir? | Address |
| -------------- | ---- | --------------- | ------- | ------- |
| Greetings      | 18b  | Howdy.txt       | N     | ~~~        |
| Documents      | ~~~  | Greetings (dir) | Y     | ~~~        |
|                | ~~~  | Documents       | Y     | ~~~        |
How it is stored in computer

```
import java.io.File;

File f = new File("example.txt");
if (f.exists() && f.length() > 1000) {
	f.delete();
}
```
Not a file in the way we think of. It doesn't actually create a new file on the hard disk. A Java File Object is talking about an ADDRESS like the above table. It doesn't even have to exist which is why you need to check.

Length is in bytes. Varies language to language

`f.delete()` actually deletes it from the hard drive. You're basically creating a file object to manipulate an actual file, but the object is not necessarily the file. It is removed from memory and the address book table.

Note: These methods only look in the specified default directory. In Eclipse this is the source folder. It doesn't check your entire hard drive. IF you don't specify. You could do something like `MyComputer\Documents\Greetings\Howdy.txt`. If you don't specify it'll assume it's in the same folder as the .java file.
The above example is a *full path*.
*Relative path* is where it assumes the file is if you don't specify. Then you'd only have to specify locations within the source folder. `\files\example.txt` assumes it's in the source folder.
*Best practice to always use relative path*. Absolute paths are usually only correct on your computer, but relative paths can be more universal.

| Method name    | Description                                                   |
| -------------- | ------------------------------------------------------------- |
| canRead()      | returns whether the file is able to be read (access controls) |
| delete()       | removes file from disk                                        |
| exists()       | whether this file exists on disk                              |
| getName()      | returns file's name (only name not full address path)         |
| length()       | returns number of bytes in file                               |
| renameTo(file) | changes name of file                                          |
renameTo(file) can also change where the file is if you put the whole directory in.

```
File evidence = new File("incriminatingEvidence.txt");

if (evidence.exists()) {
	evidence.renameTo(new File("nothingToSeeHere.txt"));
}
```

### Reading files
`Scanner name = new Scanner(new File("file name"));`
You don't need to create a new File object if you have one that already exists
```
File valsFile = new File("mydata.txt");
Scanner input = new Scanner(valsFile);
```
Or shorter:
```
Scanner input = new Scanner(new File("mydata.txt"));
```

*When dealing with IDEs, adding ".\" before the filename (".\readme.md") helps ensure that this is the folder that Java looks in*. Reduces errors by 40% roughly. Do this.

| Method          | Description                                                          |
| --------------- | -------------------------------------------------------------------- |
| hasNext()       | returns true if there is a next token                                |
| hasNextInt()    | returns true if there is a next token and it can be read as an int   |
| hasNextDouble() | returns true if there is a next token and it can be read as a double |
### Handling file errors (try/catch)
`java.io.FileNotFoundException` means it doesn't exist. 
*exception:* An object representing a runtime error. When a program has an error it *throws* an exception. You can *catch* (handle or fix) an exception
A *checked exception* is an error that MUST be handled by our program otherwise it will not compile.
	Something like dividing by 0 or accessing an index out of bounds is not checked, but reading a file that does not exist is an checked exception.

`throws` clause: Keywords on a method's header that state that it may generate an exception (and will not handle it). Fastest and also least safe way of dealing with checked exceptions
	Syntax:
	`public type name(params) throws type {`
	"I hereby announce that this method might throw an exception, and I accept the consequences if this happens." Very not the standard and a bad idea.
