## Kinds of methods
*Accessor*: A method that lets clients examine object state
	Getters
	Usually non-void return type
*Mutator*: A method that modifies an object's state
	Setter
	Side affect: A function may have some if it changes the state of anything

## Printing methods with the toString() method
It overrides the normal toString() method that prints the memory address and instead prints whatever desired outcome was put in the method
You can just do `System.out.println("p1: " + p1);` and it's actually calling p1.toString()
```
public String toString() {
	code that returns a String representing this object;
}
```
It needs to be this EXACT format

## Constructors
*Constructor*: Initializes the state of new objects
* This runs when using the `new` keyword
* no return type is specified; it implicitly "returns" the new object being created
* If a class has no constructor, Java gives it a default constructor with no parameters that sets all fields to 0 or null
	* If given any user defined constructor, the default one no longer exists. This can cause errors and bugs
```
public <classname>(parameters) {
	statements;
}
```

#### COMMON CONSTRUCTOR BUGS
1. Re-declaring fields as local variables ("shadowing")
```
public Point(int initialX, intInitialY) {
	int x = initialX;
	int y = initialY;
}
```
This is why people generally use parameters with the same name as the field variables. It prevents you from being able to create new local variables on accident by not using the this. command

2. Accidentally giving the constructor a return type. It's a valid function but it will not be recognized as a constructor and the `new` keyword will not work

## Method overloading
*Overloading* is having two functions in a class with the same name but with different signatures. The call will find the corresponding signature as the parameters in the call and execute that method
*Signatures* are the types of parameters a method accepts and what order they are in
