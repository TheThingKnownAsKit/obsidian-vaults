# Error Management
## Exceptions
An **Exception** (or exceptional event) is a problem that arises during the execution of a program. When an `Exception` occurs, the normal flow of the program is disrupted and the program terminates abnormally
	Some need to be handled, some don't.

Exceptions can be caused by:
* user error
* programmer error
* physical resources have failed
This creates three categories of Exceptions:
* Checked Exceptions
* Unchecked Exceptions
* Errors

### Checked Exception
A **Checked Exception** is an error that Java will NOT allow you to compile without being handled. It occurs at compile time and will not run.
Also called Compile-Time Exceptions.
	FileNotFoundException
	IOException (parent of FileNotFoundException, v general)
	SQLException
	ClassNotFoundException

Terminate program early or sometimes the error is recoverable.

### Unchecked Exceptions
An **unchecked exception** is an exception that occurs at the time of execution. Also called **Runtime Exceptions**.
Usually programming bugs such as logic errors or improper use of an API. Runtime exceptions are ignored at compile time. They only show up at runtime. Usually not recoverable.
	ArrayIndexOutOfBoundsException
	NullPointerException
	ArithmeticException
	DivideByZeroException
	IllegalArgumentException

You CAN choose to handle these, but the compiler will not force you to.

### Errors
These are not exceptions at all, but problems that arise beyond the control of the user or the programmer.
Errors are typically ignored in code because you can rarely do anything about it. Also ignored at time of compilation.
	StackOverflowError
	AssertionError

# Try/Catch/Finally
```
try {
	call.somethingThatCauseAnException();
} catch (TypeOfException e) {
	do.somethingToRecoverOrFailGracefully();
}
```
If multiple types of exceptions could occur, include multiple catch statements. Stack like if/else. Only checks the FIRST exception that happens
Remember SCOPES. Declare variables BEFORE the try/catch and initialize them inside it.

The Exception class has:
`public String getMessage()` a string representing what went wrong. Detailed specifics about type of exception.
`public String toString()` returns the name of the class concatenated with the result of getMessage()
`public void printStackTrace()` prints the result of toString() along with the stack trace to System.err,, the error output stream.

```
try {
	// opening the file of names
	File file = new File("E://file.txt");
	FileReader fr = new FileReader(file);
} catch (FileNotFoundException e) {
	System.out.println("Names file wasn't found:");
	e.printStackTrace();
}
```
Would just continue without doing anything (besides printing) because there was no exit or reprompt or anything like that. Likely to cause errors later in the program.
Add a `System.exit();`

USUALLY you want to use try/catch blocks. However, if you're writing an object that could throw an exception and it is too specific of an object to know how to handle it, you should use the throws exception in the class declaration. This error can then he handled wherever it was called with more information.
