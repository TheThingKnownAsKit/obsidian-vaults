# 8.1 Memory Management: Intro
A **linked list** is a list wherein each item contains not just data but also a reference - a link - to the next item in the list. Comparing ArrayLists and linked lists:
* *ArrayList:* Stores items in contiguous memory locations. Supports quick access to the i'th element via the set() and get() methods, but may be slow for inserts or removes on large lists due to necessary shifting of elements.
	* Fast get
	* Less memory
	* Slow inserts/removes
* *Linked List:* Stores each item anywhere in memory, with each item referring to the next item in the list. Supports fast inserts or removes, but access to the i'th element may be slow as the list must be traversed from the first item to the i'th item. Also uses more memory due to storing a link for each item.
	* Slow get
	* More memory
	* Fast inserts/removes

# 8.2 A first linked list
You generally have to make a linked list yourself by using objects and references.

A class is defined to represent each list item, known as a **list node.** A node is comprised of the data to be stored in each list item and a reference to the next node in the list.
A special node named head is created to represent the front of the list.
```
public class IntNode {
   private int dataVal;         // Node data
   private IntNode nextNodeRef; // Reference to the next node

   public IntNode() {
      dataVal = 0;
      nextNodeRef = null;
   }

   // Constructor
   public IntNode(int dataInit) {
      this.dataVal = dataInit;
      this.nextNodeRef = null;
   }

   /* Insert node after this node.
    Before: this -- next
    After:  this -- node -- next
    */
   public void insertAfter(IntNode nodeLoc) {
      IntNode tmpNext;

      tmpNext = this.nextNodeRef;
      this.nextNodeRef = nodeLoc;
      nodeLoc.nextNodeRef = tmpNext;
   }

   // Get location of nextNodeRef
   public IntNode getNext() {
      return this.nextNodeRef;
   }

   public void printNodeData() {
      System.out.println(this.dataVal);
   }
}
```

Example:
```
public class CustomLinkedList {
   public static void main(String[] args) {
      IntNode headObj;  // Create IntNode reference variables
      IntNode nodeObj1;
      IntNode nodeObj2;
      IntNode nodeObj3;
      IntNode currObj;

      // Front of nodes list
      headObj = new IntNode(-1); 
      
      // Insert more nodes
      nodeObj1 = new IntNode(555);
      headObj.insertAfter(nodeObj1);

      nodeObj2 = new IntNode(999);
      nodeObj1.insertAfter(nodeObj2);

      nodeObj3 = new IntNode(777);
      nodeObj1.insertAfter(nodeObj3);

      // Print linked list
      currObj = headObj;
      while (currObj != null) {
         currObj.printNodeData();
         currObj = currObj.getNext();
      }
   }
}
```
# 8.3 Memory regions: Heap/Stack
A program's memory typically contains four different regions:
* **Code:** The region where the program instructions are stored
* **Static memory:** The region where static fields are allocated. The name "static" comes from these variables not changing; they are allocated once and last for the duration of a program's execution and their addresses stay the same.
* **The stack:** The region where a method's local variables are allocated during a method call. It adds to the stack, and a return removes them. Because this is all automatic, it is sometimes called **automatic memory**.
* **The heap:** The region where the "new" operator allocates memory for objects. The region is also called **free store**.

In Java, the code and static memory are actually integrated into a region of memory called **method area.** Also stores information for every class type used in the program.
