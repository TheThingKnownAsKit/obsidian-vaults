## 6.1 User-defined method basics
A *method* is a named list of statements.
	A *method definition* consists of the new method's name and a block of statements. Ex: `public static double calcPizzaArea() { /* block of statemebts */ }`
	A *method call* is an invocation of a method's name, causing the method's statements to execute.

*Access modifiers* determine where a method can be called in a program and what values can be passed to a method. (kinda, details discussed later)
	public indicates the method may be called from any class in the program
	static indicates the method only uses values that are passed to the method

A *return statement* indicates what kind of value a method may return. For example, if a method has return type int, the method's return statement must have an expression that evaluates to an int.
	Can only return one item
	A return type of void indicates that it does not return any value

A *parameter* is a method input specified in a method definition. It is like a variable declaration. Upon a call, the parameter's memory location is allocated, and the parameter is assigned with the argument's value. Upon returning to the original call location, it is deleted from memory.
	Cannot be an expression. You can't do (int circleDiameter + 5).
	Can have multiple parameters or no parameters.
	Note: When calling a method and giving it an argument, this CAN be an expression as long as it evaluates to the correct data type. You can do calcCircleArea(diameter + 5) because it should evaluate to an integer. This is then passed to the parameter circleDiameter.
An *argument* is a value provided to a method's parameter during a method call.
Basically, a parameter is the specifications of what the method expects to receive, and the argument is what it receives.
	The parameter could be for the diameter of a circle, (int circleDiameter), and the argument is 9.5.

## 6.3 Reasons for methods
Increases readability. May add more lines of code but it's worth it. May also reduce program speed.

Programmers commonly use methods to write programs modularly and incrementally.
*Modular development* is the process of dividing a program into separate modules that can be developed and tested separately and then integrated into a single program.
*Incremental development* is the process in which a programmer writes, compiles, and tests a small amount of code, then writes, compiles, and tests a small amount more (an increment amount), and so on.
A *method stub* is a method definition whose statements have not yet been written.
	Declaring all the methods you think you'll need even if you don't make them functional yet. Sometimes writes main logic with the method stubs just to see if it would hypothetically work, even though the methods don't do anything yet.
	Use FIXME or TODO statements to help remember and organize.
		Usually print FIXME and return a placeholder value.

Good rule of thumb is that a method's definition usually shouldn't have more than about 30 lines of code. Not a strict rule.
The whole point is to break up code and avoid redundancy.

## 6.7 How methods work
Each method call creates a new set of local variables, forming part of what is known as a *stack frame*. A return causes those local variables to be discarded.

## 6.9 Array parameters
A variable of primitive type is passed to a method by passing the value of the variable, meaning the argument's value is copied into a local variable for the parameters. *As such, any assignments to parameters do not affect the arguments, because the parameter is a copy.*

An array is passed to a method by passing a reference to the array. The array reference is copied to the method's parameter, so a method can modify the elements of an array argument.
While the contents of an array (or object) parameter can be changed in a method, the array reference passed to the method cannot. A common error is to assign a method's array (or object) parameter believing that assignment will update the array argument.

*BASICALLY
Altering the parameter variables if they're primitive will not change the original.
Changing the parameter variable of a reference type WILL change the original.*

## 6.10 Scope of variable/method definitions
A variable declared in a class but not in a method is called a *field*.
If a field and a method parameter variable have the same name it will throw an error.
If a field and a method's local variable have the same name, the name will refer to the local variable.

## 6.11 Method name overloading
Sometimes a program has two methods with the same name but differing in the number or types of parameters is known as *method name overloading* or just *method overloading*.
The compiler determines which method to call based on the argument types used in the call.
	Does not apply to return type. If you have two identical methods except with different return types, it will be an error.

## 6.13 Scanner in methods
If a method needs to read user input, it's a good practice to create a single Scanner object in main() and pass that Scanner object to the method through parameter arguments.
	This is because each time a method is called, it creates all it's variables again. If you declare a Scanner in a method, it will create a scanner variable every single time it's called which can lead to slow programs or unexpected results.

## 6.18 Using references in methods
Primitive data types are stored directly in the stack frame or *stack*.
Arrays are stored indirectly in the *heap*, and only the reference to the array is stored in the stack frame.
	So asking where the array as a whole is stored, it's the stack since calling the array name will just be the reference. Asking where a specific value of an array is stored is the heap.
	This means that methods can change arrays because of the same reasons they can change reference types.
