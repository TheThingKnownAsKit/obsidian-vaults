# TREES
Terminology:
* A tree is a collection of elements (**nodes**)
* Each node may have 0 or more **successors**, also called a child
* Each node has exactly one **predecessor**, also called parent (except the starting **root**)
* Links from node to its successors are called **edges**
* Nodes with the same parent are **siblings**
* Nodes with no children are **leaves**

A **subtree** of a node is a tree whose root is a child of that node

# BINARY TREES
A **binary tree** can only have 0-2 children
	A node has at most 2 non-empty subtrees

Set of nodes T is binary if either of these is true:
* T is empty
* Root of T has two subtrees, both binary trees
* (This is recursive definition)

Trees grow from top down
New values are inserted in new leaf nodes
A binary tree is **full** if all leaves are at the same level (because it can have AT MOST 2)
A binary tree us **complete** if:
* All leaves are at level h or level h-1 (for some h)
* All level h-1 leaves are to the right 
	* If a node has 1 leaf and not 2, the leaf must be to the right?

Traversing of binary trees:
**Tree traversal** is the process of walking the tree and visiting the nodes. Note: You will always keep the tree on your left in a Euler Tour
* **Preorder** record node when you get there traveling from top down (favoring the left). The root is visited first and the last thing visited in the bottom rightmost leaf. Note the arrows circling each node
	![[Pasted image 20240220113757.png]]

* **Inorder** record after traversing the left subtree. Go all the way down the left subtree then back to the node. Traverse left, visit node, traverse right
	* Go all the way down the left subtree until there is no left node. Record node. Go down to the right, and repeat
	![[Pasted image 20240220114317.png]]
	* A has left, b has left, d does not have left so record it, go right, g has no left so record it. Back to b, go a

* **Postorder** traverse left, traverse right, visit root. Goes all the way down the left subtree and records from bottom to top, goes all the way down the right and records bottom to top, record root

# BINARY SEARCH TREES
Special case binary tree.
* Elements in left subtree < element in subtree root
* Elements in right subtree > element in subtree root

Just an ordered binary tree

Search algorithm with recursion:
1. If tree is empty, return null
2. If target equals to root node's data, return that data
3. If target < root node data, return search(left subtree)
4. Otherwise return search(right subtree)

Note: Inorder traversal for binary search trees means the nodes are visited in order of increasing data value
# HUFFMAN TREE
Represents Huffman codes for characters appearing in a file or stream
	Organizing binary for characters based on commonality (least common letters go at the end, most common at the top). This would take up more bits per letter but due to common letters being given fewer bits, it is usually more efficient
	Not really used anymore because memory is cheap now
