Tokenizer takes in something like (P|Q)|-(Q|R)|-S and outputs P|Q, |, -(Q|R), |, -S as tokens

This entire thing assumes good input. You will always have two variables per operator and parenthesis are used when order of operations are needed

Forms of tokens:
* Variables
* Not variables
* Full statements ()
* Not with parenthesis
* Sub statements

Base cases:
* If first token is a single var -> left = new VariableProposition(token)
* If first token is a not variable so length 2
* If length is >= 4 then it is a not with parenthesis
* For a full statement without a not, left = parse(token)

Handling operators:
* If tokenizer.hasNext() returns true then we know it is guaranteed to be an operator because they alternate variables and operators. Therefore, operator = tokenizer.next()
* For an and case:
	*  right = tokenizer.next()
	* if (token is &) -> left = new AndProposition(left, parse(right))
	* Same for the other ones


Not always connected to something, doesn't count as a operation in of itself so there's never two operations in a row.
