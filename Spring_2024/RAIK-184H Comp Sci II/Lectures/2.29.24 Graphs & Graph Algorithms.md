# GRAPHS AND SPANNING TREES
A **graph** is an unstructured series of connected data. Thing's like trees and maps are all graphs, but not all graphs are trees/maps
* Any node can have an edge to any other node
* There is no concept of "root"
* Edges can have weights
	* Distance, travel time, etc
	* Can technically have negative weights but oh god

Examples:
	Social networks, roads, webpages

Terminology:
* **Vertex** - a node
* **Vertex Set** - V
* **Edges** - connections between nodes
* **Edge set** - E pairs of vertices which are connected
* If G is **directed**, they are ordered pairs where u->v, (u, v)
* If g is **undirected**, they are UNORDERED pairs where u-v, {u, v}

T is a **spanning tree** of graph G if
1. T is a directed tree with the same vertex set as G
2. each edge of T is a directed version of an edge of G
Basically structuring the unstructured data I think? Used for path-finding, searching, etc

# DEPTH-FIRST SEARCH
**Depth-First Search (DFS)** finds a path between two vertices by exploring each possible path as far as possible before backtracking
* Uses STACK to store nodes that have been seen, but not yet visited
* Usually uses recursion

Requires two pieces:
1. A get-neighbors function that determines which neighbor the algorithm will visit. Implementation varies, examples are:
	1. Right-most first
	2. The neighbor with the most/fewest shared ancestors
	3. Alphabetical order
		1. Start at a random vertex. Look at all neighbors and pick the first alphabetical vertex that you have NOT VISITED. Will NOT consider vertex's already visited
			1. Look at the first node in the stack
			2. Mark current node VISITED
			3. Proceed to the first unvisited neighbor, then push them to the stack. If there are no unvisited neighbor, pop the current vertex and go backwards (to son) until there's an unvisited neighbor
	4. Random order

DFS Observations
* *Traversal:* DFS is guaranteed to reach all the nodes in a connected component
* *Search/Retrieval*: If you are looking for a specific node (rather than trying to visit all of the nodes) it is easy to retrieve exactly what the path is (sequence of edges) if we find it (the stack is the path)
* *Optimality*: not optimal. DFS is guaranteed to find a path, not necessarily the best/shortest path
* *Determining connectivity*: start a DFS at a random vertex and determine, once the algorithm halts, whether all nodes have been visited. If they have, the graph is connected. If the haven't, it is unconnected
* *Performing a traversal of a connected graph*: You're guaranteed to visit all the nodes if the graph is connected
