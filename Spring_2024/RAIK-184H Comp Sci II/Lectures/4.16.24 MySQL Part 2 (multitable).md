# DESIGNING DATABASES WITH MULTIPLE TABLES
## Making Java objects compatible with SQL tables
<mark style="background: #BBFABBA6;">To do so, you probably need multiple objects when converting between database style to Java. Do's:</mark>
* Every object/enum should be a table
* Every table should have an auto-incremented INT field called "id". This is the PRIMARY KEY
* If a <mark style="background: #ADCCFFA6;">one-to-one relationship</mark> exists between tables A and B (A has a B, every student has one phone and doesn't share or swap)
	* add a column in A called b_id that will hold the Id of the related B row in the B table. This is called a <mark style="background: #ADCCFFA6;">foreign key</mark>. The use of a different unique identifier in your table
	* A is usually the more important thing, bigger objects will reference B. Student has a phone_id not the other way around
* If a <mark style="background: #ADCCFFA6;">one-to-many or many-to-many relationship</mark> exists between A and B (A has many Bs or many As have many Bs), you need to create a <mark style="background: #ADCCFFA6;">relationship table</mark> that contains an id, foreign keys for A and B, and any other metadata about the relationship
	* Many stores and each store had many clothing items to sell. You'd need a relationship table that would include id, store_id, item_id, quantity, etc

Don't forget to declare something as a foreign key if needed in the database.
