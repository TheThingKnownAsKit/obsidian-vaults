## More Memory and Instructions
Byte ordering is not relevant to strings because it is not a multibyte type, it is an array of 1-byte chars aka a pointer to a char

Programs are byte sequences -> encode program as sequence of instructions -> each instruction is a simple operation (arithmetic, read/write, conditional branch) -> Instructions encoded as bytes
* ARM, PowerPC use 4 byte instructions
	* Reduced Instruction Set Computer (RISC)
	* Makes it very fast if every instruction is the same length, though can waste memory
* x86-64 uses variable length instructions
	* Complex Instruction Set Computer (CISC)
	* Slower, saves memory

## Bit Operations

| Operation      | Logical  | Bitwise |
| -------------- | -------- | ------- |
| AND            | a && b   | a & b   |
| OR             | a \|\| b | a \| b  |
| NOT/COMPLEMENT | !a       | ~a      |
| XOR            |          | a ^ b   |
Bitwise operations deal with the individual bits represented by an integer, while logical operations deal with integer values

SHIFTS:
* <mark style="background: #ADCCFFA6;">Left Shift</mark>       x << y
	* Move x’s bits to the left by y positions
	* Fill with 0s on the right
	* Truncate excess bits on left
* <mark style="background: #ADCCFFA6;">Right Shift</mark>     x >> y
	* Move x’s bits to the right by y positions
	* Truncate excess bits on the right
	* In LOGICAL SHIFT: fill with 0s on the left
		* Add on u to the end of a hex value to make it unsigned and indicate logical shift (0xAu is the unsigned version of 0xA in notation)
	* In ARITHMETIC SHIFT: duplicate leftmost bit (to keep sign if twos-complement)

<mark style="background: #ADCCFFA6;">Bitmasks</mark> are using a sequence of bits to manipulate the bits of another value. If you want to examine if one specific bit is a 0 or 1, you can do a bitwise operations with a known sequence (1, hex value, etc) to obtain either 0 or 1 aka true/false
